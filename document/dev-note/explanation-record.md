# Dotori Agent - 구현 설명 기록

## 구현 후 나오는 결과물

### 1. 동작하는 에이전트 엔진 흐름
```
사용자 요청: "Order.java 레거시 코드를 Spring Boot 3 DDD로 변환해줘"
    ↓
에이전트 루프 실행:
  1. onRequest 훅 → 의도 분석 (코드 변환 작업임을 인식)
  2. read_legacy_spec_and_code 도구 → 레거시 코드/명세서 읽기
  3. LLM → 변환된 코드 생성
  4. beforeSend 훅 → 토큰 60% 감지, 대화 내역 자동 압축
  5. run_sandbox_compiler_and_test 도구 → 컴파일/테스트 실행
  6. onToolResult 훅 → 테스트 실패 감지, 1회차 기록
  7. ERROR_CORRECTION_INSTRUCTION → 에러 원인 분석 후 재시도
  8. 2회차 → 테스트 통과 ✅
    ↓
결과: 변환된 Java 코드 + 변경 요약
```

### 2. 핵심 파일 구조
| 파일 | 무엇을 만드나 | 배울 것 |
|------|-------------|---------|
| hooks/base.py | 훅 인터페이스 + 4가지 훅 구현 | 이벤트 기반 아키텍처, 생명주기 제어 |
| agent/session.py | 세션 격리 + 컨텍스트 슬라이딩 | 토큰 관리, 컨텍스트 윈도우 최적화 |
| agent/graph.py | LangGraph 상태 머신 | State Machine 패턴, 조건부 라우팅 |
| tools/shell.py | 범용 Shell 도구 + 스킬 로딩 | 도구 설계, 확장성 패턴 |
| agent/sub_agent.py | 서브에이전트 위임 | 분산 에이전트, 컨텍스트 오염 방지 |

## 이해하게 되는 것

### 1. 에이전트 아키텍처 설계
- **훅(Hook) 기반 제어**: 거대한 if-else 대신 이벤트로 분리하는 방법
- **세션 격리**: 여러 작업을 독립적으로 관리하는 패턴
- **컨텍스트 관리**: 토큰 초과 방지 + 성능 유지 전략

### 2. LangGraph 활용법
- `StateGraph`로 상태 머신 구현
- `Node` + `ConditionalEdge`로 흐름 제어
- 체크포인트로 세션 상태 저장/복원

### 3. 자기수정(Self-Correction) 루프
- 에러 로그 분석 → 원인 파악 → 수정 → 재시도
- 무한 루프 방지 (MAX_RETRY + 훅 가드레일)

### 4. 확장성 패턴
- 도구 추가 vs 스킬 문서 추가 (도구 폭발 방지)
- 서브에이전트로 작업 위임 (컨텍스트 오염 방지)

## 검증 방법

구현 후 다음으로 확인 가능:
1. **훅 트리거 확인**: 로그로 beforeSend, onToolResult 등이 실제로 동작하는지
2. **컨텍스트 관리**: 토큰이 80% 넘어가면 자동 압축되는지
3. **자기수정**: 테스트 실패 시 3회까지 재시도하는지
4. **서브에이전트**: 대량 파일 탐색 시 메인 컨텍스트가 50% 이하 유지되는지

## 결론

이 실습을 통해 **단순한 Chatbot이 아닌, 프로덕션 레벨의 에이전트 엔진**을 직접 설계하고 구현하게 됩니다. 실제로 OpenAI Assistants API, LangChain, CrewAI 등에서 사용하는 패턴들을 직접 코드로 익히는 거죠.
