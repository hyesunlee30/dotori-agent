1. 훅(Hook) 기반 가드레일 및 이벤트 제어 아키텍처 구현
   턴 루프 전체를 하나의 거대한 코드 블록으로 작성하지 않고, 생명주기 이벤트(Lifecycle Events)와 훅(Hook) 구조로 분리하여 제어권을 갖도록 실습해보기 가장 좋습니다.

실습 내용:

onRequest 훅: 사용자 입력을 전달받았을 때 프롬프트 리라이팅(Prompt Rewriter) 및 의도 분석 수행.

beforeSend 훅: 모델 전송 직전 컨텍스트 토큰 사용량 체크. 50~80% 초과 시 대화 내역 자동 압축(Compaction) 처리.

onToolCall 훅: 도구 실행 전 인자(Argument) 가드레일 검사 및 보안 검증.

onToolResult 훅: 동일한 도구가 연속/무한 반복 호출되는지 감지하고, 3회 이상 반복 시 "다른 접근법을 시도하세요"라는 리마인더(Reminder) 메시지 강제 삽입.



2. 컨텍스트 오염 방지를 위한 서브에이전트(Sub-Agent) 패턴 적용
   메인 대화 세션 하나에서 모든 도구 호출과 탐색 과정을 처리하면 컨텍스트 윈도우가 금방 오염되고 성능이 급격히 떨어집니다.

실습 내용:

복잡하거나 턴이 많이 소모되는 작업(예: 대량의 코드 파일 탐색, 로그 분석, 외부 문서 검색 등)을 독립된 세션을 가진 서브에이전트에게 위임.

서브에이전트는 내부적으로 여러 턴을 거쳐 도구를 사용한 뒤, 최종 요약 결과만 메인 세션으로 반환.

메인 에이전트의 컨텍스트를 깨끗하게 유지(50% 이하)하여 전체적인 성능과 정확도를 유지하는 패턴 구현.


3. 목표(Goal) 기반 자율 평가 및 재시도 루프 (Self-Reflection)
   사용자의 요청에 대해 단 한 번의 턴으로 끝내는 것이 아니라, 목표 달성 여부를 스스로 평가하고 필요시 새로운 턴을 일으키는 루프를 구축합니다.

실습 내용:

턴이 끝나는 시점에 자아성찰(Self-Correction) 상태 검사 수행.

"작성된 코드가 테스트를 통과했는가?", "사용자가 요구한 조건을 모두 충족했는가?"를 판정.

목표 미달성 시, 모델 스스로 새로운 프롬프트/요청을 생성하여 요청 큐(Request Queue)에 삽입하고 다음 턴을 계속 이어가도록 제어 logic 구현.


4. 도구 폭발(Tool Explosion)을 막는 범용 도구(Shell) + 스킬(Skills) 구조
   각 기능마다 도구(Function Call)를 무한정 추가하면 도구 선택 장애 및 역할 충돌이 발생합니다.

실습 내용:

실행 도구는 Terminal / Shell 또는 기본 프로세스 실행 도구 1~2개로 최소화.

대신 도구 사용법, 명령어 조합, 특정 가이드라인을 작성한 스킬(Markdown/Text 문맥 문서)을 구축하고, 모델이 필요할 때 스킬을 동적으로 읽어와 실행하도록 구조화 (Claude Code 방식).

도구 구현 부담을 줄이면서 확장성을 대폭 향상 가능.


5. 비동기 도구 실행 및 작업 대기 큐 (Async Queue & Steering)
   시간이 오래 걸리는 작업(빌드, 통합 테스트, 대용량 파일 다운로드 등)을 도구로 실행할 때 에이전트가 블록킹(Blocking)되는 현상을 방지합니다.

실습 내용:

도구 실행을 메인 프로세스와 분리된 별도 프로세스/비동기 큐로 처리.

작업 진행 상태를 이벤트 스트리밍으로 수신하며, 대기하는 동안 사용자가 새로운 프롬프트나 인터럽트(중단/지시 변경)를 주더라도 에이전트가 즉시 반응할 수 있는 이벤트 대기 상태 체계 구축.



1단계 (기본): 턴-이터레이션-세션 구조 구현 + beforeSend/onToolResult 훅 적용 (컨텍스트 관리 및 반복 방지)

2단계 (고도화): 범용 도구 + 스킬 문서 로딩 구조 설계

3단계 (심화): Goal 자아성찰 루프 및 서브에이전트 위임 패턴 추가
